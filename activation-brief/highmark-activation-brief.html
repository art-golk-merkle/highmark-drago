Developer guide

Code, architecture and tooling of the AEM Edge Delivery Services site

The developer guide covers the code that maintains and extends the Highmark website on AEM Edge Delivery Services: the content structures the code depends on, and the tooling that builds generated content. Dated October 21, 2026.

Architecture overview

  • Tech stack: vanilla JavaScript (ES modules) and CSS with custom properties. No build step, no framework, no runtime dependencies. Content comes from Document Authoring (DA) and is rendered by the Edge Delivery Services pipeline into semantic HTML that the code decorates.
  • Project structure: 40 block folders (29 project blocks, 11 untouched boilerplate), core scripts in scripts/ (aem.js, scripts.js, delayed.js), 34 page-template stylesheets in styles/templates/, 14 SVG icons, and CI in .github/workflows/main.yaml that lints on every push.
  • Loading phases: head (CSP, Adobe Fonts kit, aem.js, scripts.js, styles.css); eager (template classes and stylesheets, decorators, first section); lazy (modal links, remaining sections, header, breadcrumbs, footer, ZIP tokens); delayed (delayed.js after 3 seconds, the only place for third-party scripts).
  • Content Security Policy: set in head.html as an HTTP header. A script tag added directly to head.html needs nonce="aem".
  • Templates: each Template value in page metadata becomes a body class. Listed stylesheets come from TEMPLATE_STYLES in scripts.js. Adding a template needs a file in styles/templates/ and an entry in that list.
  • Client storage and URL state: localStorage key shop-zip-county holds the visitor's ZIP selection; the zip-county-submit event carries it; search and press release filters use URL parameters.

Local development

  • Prerequisites: Node.js 20 (CI uses 20; the tools need at least 18), AEM CLI (npm install -g @adobe/aem-cli), and Git with LF line endings.
  • Setup: clone AdobeDrago/highmark, run npm install, then aem up to serve on http://localhost:3000 with preview content.
  • Linting: npm run lint runs ESLint (airbnb-base) and Stylelint. CI runs the same command on every push.
  • Credentials: nothing is stored in the repo. Preview and publish use the AEM Sidekick or the DA editor with your Adobe account.

Design system

  • Tokens: brand tokens live in styles/brand.css: Sofia Pro for headings, Roboto for body, Highmark navy (#003963) for headings, Highmark blue (#0066B1) for links, and section tints for light, blush, splash, and paper grey.
  • Breakpoints: phone below 768px, tablet from 768px (64px gutters), desktop from 992px, and wide from 1200px and 1366px. Use 768 and 992 for new work.
  • Fonts: Sofia Pro and Roboto come from the Adobe Fonts kit. The kit stylesheet is render-blocking, kept on purpose to match highmark.com's font metrics.
  • Pixel matching: most page layouts carry the source site's measured values directly in template and block CSS. Keep unitless line heights unitless.

Blocks

  • Project blocks: 29 blocks, including hero-minimal-dark-withimg (the largest block CSS, restyled by 13 templates), cards variants, columns variants, accordion, table compare, breadcrumbs, search, press-release-list, provider-list, provider-panel, provider-sidenav, forms-library, form-minimal-light, zip-county-form, zip-modal, enrollment-form, and flip-cards.
  • Boilerplate: 11 blocks from the AEM Block Collection are untouched. Only columns, table, fragment, and modal are used live, and each is restyled by templates or used through links.
  • Adding a block: create blocks/<name>/<name>.js and .css, build a test page in DA, check at 390, 768, 992, and 1280, add a Library entry under /docs/library/blocks/, then lint and open a PR.
  • Cross-block dependencies: loadFragment is used by modal, zip-modal, and the shop header and footer. zip-store and zip-tokens are used by the shop header and footer and zip-county-form. When you change a block's base CSS, search styles/templates/ for its class.

Header, footer and the ZIP and region layer

  • Layout detection: header and footer pick a layout from the shape of the fragment named in nav or footer metadata. Sections are read by position, not by name, so reordering a fragment's sections breaks its layout.
  • Header height: styles.css reserves header height before load, keyed on the literal nav value. A new header fragment path needs a rule there, or the page shifts when the header loads.
  • ZIP flow: /modals/zip-county hosts zip-county-form, which reads the shop sheets and writes localStorage. applyZipTokens fills {{token}} values in links and text, shows regional sections only for matching region codes, and writes the location line.
  • ZIP data: interim, built from Census 2020 ZIP-to-county data with county-to-region tables hard-coded from Highmark's service-area map. Replace it with the enGen list when it arrives, keeping the same columns.

Generated content and tooling

  • Read-only by default: tools under tools/ are Node ESM scripts run as node tools/<dir>/<script>.mjs. Writes happen only with --upload or --apply, and they write to DA and preview, never publish (except provider-import live).
  • Redirects (critical): build-redirects.mjs crawls live pages and fragments, finds links that 404 on live, and writes the /redirects sheet. Any path with a DA document gets no row, so an unpublished draft 404s once the regenerated sheet is published. Never hand-edit the sheet.
  • Refresh steps: provider lists (re-run, publish the five sheets, rebuild and publish redirects); press releases and events; ZIP data (check the shop on preview, then publish both sheets); after publishing new pages, regenerate redirects and re-index pages published while redirected.
  • Migration tooling: importers for about 40 templates, 20 block parsers, and provider-import with Playwright. Keep until the remaining highmark.com and provider pages are migrated. sync-sidenav.mjs overwrites hand edits and should be retired at cut-over.

Testing, CI and git workflow

  • CI: lint only, on Ubuntu with Node 20. No tests run in CI and there is no deploy step. Code reaches preview and live through the AEM Code Sync app when a branch is pushed.
  • Test suites: Playwright scripts in tools/tests/, covering regression at 1280 and 390, search, ZIP and region behavior, provider pages and lists, link checks, and axe-core accessibility (WCAG 2.1 A/AA). Run them against aem up --port 3100.
  • Workflow: branch off main, run lint and the relevant suites, open a PR with branch preview URLs, then squash-merge. Code goes live on merge; content needs its own preview and publish.

Common developer tasks

  • Add a template: create styles/templates/<name>.css with every rule scoped to body.<name>, add the name to TEMPLATE_STYLES, and add a body-class decorator in loadEager only if JS is needed.
  • Add a section style: add .section.<style> rules to styles.css (global) or the template file (scoped), then document the value for authors.
  • Add analytics or a marketing tool: load it from scripts/delayed.js only, and check it under the CSP.
  • Debug a block: check the console and Network tab for 404s on /blocks/<name>/<name>.{js,css}, compare the block's .plain.html with what the JS expects, and check data-block-status.

Known issues

  • Forms cannot submit: form-minimal-light POSTs to a highmark.com endpoint that returns no CORS header and expects a reCAPTCHA token. Failures are logged to the console only, so visitors see no message.
  • Universal Editor branch: scripts.js top-level-awaits /ue/scripts/ue.js on *.ue.da.live hosts, but ue/ was deleted, so page load fails there.
  • Shop header heights: the dental and blue-edge-balance shop headers do not match the /shopx-header height rule, so the page shifts on load.
  • Silent truncation: hard-coded sheet limits cut data quietly: ZIP sheet at 10,000 rows, search and query indexes at 5,000, press releases at 1,000.
  • Fragile coupling: many template rules are keyed on heading IDs, and some code classes content by matching authored text. Rewording those headings changes the layout.
  • Performance: breadcrumbs make N+1 requests, the search index is downloaded whole (about 280 KB compressed for about 285 pages), and a full migration of about 1,400 pages would need a search service.
Author guide

Authoring highmark.com, Shop and Providers in Document Authoring

The author guide covers how content is written and published. Pages are edited as documents in DA. Layouts, blocks, and styles are code, maintained by the development team. Dated October 21, 2026.

Who changes what

  • Authors edit in DA: page text, images, blocks, and metadata; FAQ answers; glossary terms; search suggestions; shop ZIP form labels; form field sheets; modal pages under /modals/.
  • Development team owns: the /redirects sheet, corporate, shop, and provider headers and footers, ZIP and region sheets, shared provider fragments, provider list and press release sheets, new blocks and templates, form submission addresses, and the search index setup.

Getting started

  • Access: Document Authoring access to the adobedrago/highmark site, and a role for preview and publish. Ask the site administrator. The AEM Sidekick extension is optional.
  • How a page is built: a DA document is one page, and its path is its URL. Sections are split by horizontal rules. Blocks are tables whose first row names the block. Section Metadata and Page Metadata are small tables.
  • First page: copy a live page of the same kind, which brings the right blocks, sections, and metadata. Edit text and images, keep one H1, check Title, Description, and Template, then Preview and Publish.

Sections and page metadata

  • Section styles: light, accent, light-blue, blue, highlight, dark, grey, and center. Styles are typed in lowercase with hyphens. An unknown style does nothing.
  • Template-only styles: for example faq right-rail, spacers, glossary-letters, provider notice and spotlight, and topic-hub-landing hero-wide. Use them as the example pages do.
  • Page metadata: Title and Description are required. Template is usually required. Breadcrumbs: true turns on the breadcrumb trail. Breadcrumb Title sets the short label. Theme: shop turns on the ZIP modal and region links.

Blocks

  • Inserting: use the Blocks entry in the DA Library panel. Each Highmark block lists real example variants. Do not use the starter blocks from the AEM Block Collection (Accordion, Carousel, Embed, Form, Hero, Quote, Tabs, Video); use Accordion Minimal Light, Hero Minimal Dark Withimg, and Form Minimal Light instead.
  • Heroes: Hero Minimal Dark Withimg takes one image, or three in order desktop, tablet, mobile. Only the first image's alt text is used. Hero Minimal Light is a light blue title band with a centered H1 and intro.
  • Cards: Cards Minimal Dark Withimg (image, heading, text, CTA), Cards Minimal Dark Withimg 2 (two wide promo cards), Cards Minimal Dark Withimg Icons, Cards Minimal Dark List (text-only cards), and Cards Minimal Dark Iconnav (navy quick-link bar).
  • Columns and accordions: Columns Minimal Dark (text beside a photo), Columns Minimal Dark Overlay (text over a full-width photo), Accordion Minimal Light (FAQ question and answer rows), and Table Minimal Dark Compare for comparison tables.
  • Navigation and panels: Cards Minimal Light Sidenav (left-hand section menu), Provider Sidenav, Provider Panel, Provider List, and Press Release List. Search and Forms Library render the results and form lists.
  • Forms: Form Minimal Light holds a field sheet with ten columns: Name, Type, Label, Placeholder, Value, Options, Mandatory, Style, Id, Fieldset. A missing column breaks the form. Do not change the submit address.
  • Other: Fragment (shared content by path), Alert Banner (one per page, at the top of the first section), and modals (create /modals/<name> and link to it; the link opens as a pop-up).

Links, icons and headings

  • Buttons: a link alone in its paragraph becomes a button. Bold is the filled button on most pages. Lists of links go in one paragraph with Shift+Enter line breaks.
  • Relative links: link to pages on this site with relative paths. An absolute highmark.com link leaves the site even when the page exists here.
  • Icons: :pdf: after PDF links, :lock: after items behind the Availity login, :external-link: on FAQ links that should open a new tab.
  • Headings: each heading gets an ID from its text, so link with # plus the ID. Some layouts are keyed to heading text. Ask the development team before renaming those headings.

Publishing

  • Preview, then publish: saving in DA changes neither preview nor live. Preview checks your change on aem.page, and Publish puts it on aem.live.
  • Fragments and sheets: publishing a page does not publish the fragments, modal pages, or sheets it uses. Publish each one you changed. Sheet URLs end in .json.
  • Shared documents: /index, /nav, and /footer are used by every visitor. Preview each one and compare it with live before publishing. If it holds changes you did not make, check version history and ask the team.
  • Bulk: paste many URLs into the bulk tool at da.live/apps/bulk to preview or publish them together.
  • Redirects: a redirect row hides a page at the same path. Ask the development team to regenerate and publish /redirects with any new page. Deleting or moving a page needs a redirect from the old URL first.

Shop pages and the ZIP modal

  • ZIP modal: on every page with Theme: shop, the modal opens until the visitor chooses a ZIP code and county. The choice is saved in the browser. Any link to /modals/zip-county opens it again.
  • Regions: eight regions (WPA, CPA, SEPA, NEPA, DE, WV, WNY, NENY). Add a Regions row to Section Metadata with region codes to show a section only to those visitors. Use none for visitors who have not chosen a ZIP.
  • Region tokens: use {{zip}}, {{county}}, {{region-code}}, {{brand}}, {{brochure}}, and similar in link URLs only. A line with an empty token stays hidden for that region.
  • Shop page templates: shop-home (plan cards, location line, learn-more), shop-page (info pages and enrollment forms), and flip-cards for life-event pages.

Providers and page templates

  • Provider pages: landing pages use Template: providers. Content, manual, and news pages use Template: provider-content, with a Provider Sidenav block first, then the article, then an optional rail. News articles start with a topic link, the H1, region codes, and a Published Date line.
  • Corporate templates: home, about-article, leadership, leadership-bio, topic-hub-landing, topic-hub-subnav, spending-account, faq, glossary, legal, contact, media-contacts, and employer and campaign templates. Copy the example page for each.
  • Regional member pages: Template: member-regional, with nav and footer set to that region's fragments. Sub-pages use faq or legal with member-subpage as the second value.
  • Default layout: pages with no template get the site's default layout.

Configuration sheets

  • Authors update: /metadata (bulk metadata by URL pattern, only after checking with the team), /search-suggestions (suggestion and link), /shop/zip-county-form (labels and button text, keeping the field names), and form field sheets.
  • Development team generates: /redirects, /shop/regions, /shop/zip-counties, provider list sheets, press release and event sheets, and /docs/library/blocks.

Images and media

  • Adding images: drag into the DA editor, or replace in place. Images are stored in the page's dot-folder. Always add alt text.
  • Sizes: Cards Minimal Dark Withimg uses 470 by 200 for two across and 370 by 200 for three across. Cards Minimal Dark Withimg 2 crops to fill, so keep the subject centered. SVG files over 40 KB are rejected.
  • Share image: if you set Image in metadata, it must load on preview or the share image breaks. Leave the row out to use the first image.
  • Video: a link to an .mp4 alone in a Columns Minimal Dark cell plays inline. YouTube and Vimeo embeds are not styled yet.
